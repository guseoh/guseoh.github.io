## 1. 프로그램과 프로세스는 무엇이 다를까?

프로그램은 디스크에 저장된 실행 파일과 데이터다. 실행하지 않은 프로그램은 CPU 시간을 사용하거나 실행 상태를 가지지 않는다.

프로세스는 운영체제가 프로그램을 실행하기 위해 만든 실행 단위다. 같은 프로그램을 두 번 실행하면 실행 파일은 하나지만 프로세스는 두 개가 될 수 있다. 각 프로세스는 서로 다른 PID와 주소 공간, 레지스터 값과 운영체제 자원을 가진다.

```text
프로그램
└─ 디스크에 저장된 명령어와 정적 데이터

프로세스
├─ 실행 중인 명령어
├─ 독립된 주소 공간
├─ CPU 레지스터 문맥
├─ 열린 파일과 입출력 상태
└─ 운영체제가 관리하는 식별자와 상태
```

운영체제는 프로세스라는 추상화를 통해 하나의 물리 CPU에서도 여러 프로그램이 각각 자신의 CPU를 사용하는 것처럼 실행되게 한다. 멀티코어에서는 여러 프로세스가 실제로 동시에 실행될 수도 있고, 각 코어에서는 스케줄러가 프로세스를 번갈아 실행한다.

## 2. 프로세스의 실행 상태

프로세스가 중단된 뒤 같은 지점에서 다시 실행되려면 실행 중이던 상태를 보존해야 한다. 이 상태를 기계 상태 또는 CPU 문맥이라고 부른다.

### 2.1 프로그램 카운터와 레지스터

프로그램 카운터는 CPU가 실행할 명령어의 위치를 나타내는 레지스터다. 아키텍처에 따라 명령어 포인터라고 부르기도 한다.

일반 목적 레지스터에는 연산 중인 값과 주소가 들어 있고, 스택 포인터는 현재 스택 위치를 가리킨다. 운영체제가 프로세스를 멈출 때 이 값을 저장하지 않으면 나중에 이전 실행 지점으로 돌아갈 수 없다.

### 2.2 주소 공간

주소 공간은 프로세스가 접근하는 메모리 주소의 범위다. 일반적인 사용자 프로세스의 주소 공간은 다음 영역으로 설명할 수 있다.

* 코드 영역에는 실행할 기계어 명령이 저장된다.
* 데이터 영역에는 전역 변수와 정적 데이터가 저장된다.
* 힙은 실행 중 동적으로 확보한 메모리에 사용된다.
* 스택은 함수 호출 정보, 매개변수와 지역 변수 등에 사용된다.

실제 메모리 배치와 영역의 세부 구성은 운영체제, 실행 파일 형식, 언어 런타임에 따라 달라질 수 있다. Java의 객체 힙은 JVM이 관리하는 런타임 영역이며, 운영체제 관점에서는 JVM 프로세스가 확보한 주소 공간 안에 존재한다.

### 2.3 운영체제가 관리하는 자원

프로세스는 메모리와 레지스터만으로 구성되지 않는다. 운영체제는 다음 정보도 프로세스와 연결해 관리한다.

* PID와 부모 프로세스 ID
* 현재 상태와 스케줄링 정보
* 열린 파일 디스크립터
* 사용자와 그룹 같은 자격 정보
* 신호 처리 상태
* 사용한 CPU 시간과 자원 통계

프로세스를 단순히 “메모리에 올라간 프로그램”이라고만 설명하면 이 관리 정보와 실행 문맥이 빠진다.

## 3. PCB는 무엇을 저장할까?

운영체제는 프로세스별 관리 정보를 커널 자료구조에 저장한다. 교재에서는 이를 프로세스 제어 블록(Process Control Block, PCB)이라고 설명한다.

PCB에는 일반적으로 다음과 같은 정보가 포함된다.

* PID와 프로세스 상태
* 프로그램 카운터와 저장된 레지스터 값
* 주소 공간을 관리하기 위한 정보
* 스케줄링 우선순위와 CPU 사용 정보
* 열린 파일과 입출력 관련 정보

운영체제마다 실제 자료구조의 이름과 필드 구성은 다르다. PCB는 특정 구조체 이름이라기보다 프로세스를 중단하고 다시 실행하며 자원을 회수하기 위해 운영체제가 유지해야 하는 정보를 묶어 설명하는 개념이다.

## 4. 프로세스 상태

프로세스는 항상 CPU에서 실행되고 있지 않다. 기본적인 상태는 실행, 준비와 대기로 나눌 수 있다.

| 상태 | 의미 |
| --- | --- |
| 실행(Running) | CPU에서 명령어를 실행하고 있다. |
| 준비(Ready) | 실행할 수 있지만 CPU를 할당받지 못했다. |
| 대기(Blocked) | 입출력 완료나 특정 이벤트를 기다리고 있다. |

### 4.1 실행과 준비 상태 전이

실행 중인 프로세스가 CPU 사용 시간을 모두 사용하거나 더 높은 우선순위의 작업에 CPU를 넘기면 준비 상태로 이동할 수 있다. 준비 큐에서 선택된 프로세스는 CPU를 할당받아 실행 상태가 된다.

```text
준비 ── 스케줄러가 선택 ──> 실행
실행 ── 선점 또는 시간 할당량 종료 ──> 준비
```

실행할 프로세스를 선택하는 기준이 스케줄링 정책이고, 실제로 CPU 문맥을 저장하고 복원하는 동작이 문맥 교환 메커니즘이다.

### 4.2 실행과 대기 상태 전이

프로세스가 디스크 입출력이나 네트워크 응답처럼 즉시 완료되지 않는 작업을 요청하면 대기 상태가 될 수 있다. 이벤트가 완료되면 바로 실행되는 것이 아니라 준비 상태로 이동한 뒤 스케줄러의 선택을 기다린다.

```text
실행 ── 입출력 또는 이벤트 대기 ──> 대기
대기 ── 이벤트 완료 ──> 준비
```

이 흐름 덕분에 한 프로세스가 입출력을 기다리는 동안 다른 프로세스가 CPU를 사용할 수 있다.

## 5. 문맥 교환

문맥 교환은 실행 중인 프로세스의 CPU 문맥을 저장하고 다른 프로세스의 문맥을 복원하는 과정이다.

```text
Process A 실행
→ A의 레지스터 문맥 저장
→ 스케줄러가 Process B 선택
→ B의 레지스터 문맥 복원
→ Process B 실행
```

문맥 교환에는 레지스터 저장과 복원, 커널 자료구조 접근과 주소 공간 전환 같은 비용이 든다. 운영체제는 CPU를 여러 프로세스에 나누어 주면서도 전환 비용이 지나치게 커지지 않도록 스케줄링해야 한다.

문맥 교환은 프로세스의 코드를 처음부터 다시 실행하는 작업이 아니다. 저장된 프로그램 카운터와 레지스터 값을 복원하므로 이전에 중단한 위치에서 실행을 이어간다.

## 6. 생성과 종료 상태

운영체제는 실행·준비·대기 외에도 프로세스 생성과 종료를 표현하는 상태를 둘 수 있다.

새 프로세스는 커널 자료구조와 주소 공간을 준비한 뒤 실행 가능한 상태가 된다. 프로세스가 종료하면 실행에 사용하던 자원은 정리되지만, Unix 계열 운영체제에서는 부모가 종료 상태를 회수하기 전까지 PID와 종료 정보가 좀비 상태로 남을 수 있다.

좀비는 실행 중인 프로세스가 아니며 CPU를 사용하지 않는다. 부모가 `wait()` 또는 `waitpid()`로 종료 상태를 회수하면 남아 있던 커널 정보도 정리된다.

## 7. 프로세스를 관찰하는 방법

Linux에서는 `ps` 명령이나 `/proc` 파일 시스템을 통해 프로세스 정보를 확인할 수 있다.

```bash
ps -eo pid,ppid,stat,comm
```

```text
PID   PPID STAT COMMAND
1        0 Ss   systemd
842      1 S    sshd
1540   842 R+   ps
```

`PID`는 프로세스 식별자, `PPID`는 부모 프로세스 식별자다. `STAT` 값은 Linux가 표현하는 세부 상태 코드이므로 앞에서 설명한 세 상태보다 더 구체적일 수 있다.

## 8. 정리

* 프로그램은 디스크에 저장된 명령어와 데이터이고, 프로세스는 운영체제가 이를 실행하기 위해 만든 관리 단위다.
* 프로세스는 주소 공간뿐 아니라 프로그램 카운터, 레지스터 문맥, 열린 파일과 운영체제 관리 정보를 가진다.
* 운영체제는 PCB에 프로세스를 중단하고 다시 실행하는 데 필요한 상태를 저장한다.
* 프로세스는 실행·준비·대기 상태를 오가며, 이벤트가 완료된 대기 프로세스는 준비 상태로 이동한다.
* 문맥 교환은 현재 프로세스의 실행 상태를 저장하고 다른 프로세스의 상태를 복원하는 과정이다.
